# Configuration reference

All runtime configuration is via environment variables, read by the
`Settings` class in [panel/app/config.py](../panel/app/config.py) (using
`pydantic-settings`). Compose pulls them from `panel/.env`, which
`deploy.sh` generates from `/root/.panel-secrets.env` + your overrides.

> **Tip**: the validator in `config.py` refuses to start with
> `PANEL_ENV=production` and any insecure default still in place
> (default JWT secret, default admin password, missing Reality keys,
> `PANEL_HOST=panel.example.com`). This is intentional — it has caught
> "we forgot to set X" deploys repeatedly.

## Required in production

| Var                          | What it is                                                                                                                                                       |
|------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `PANEL_ENV`                  | `dev` for local docker-compose; anything else (e.g. `production`) flips on the strict validator and switches the session cookie to `Secure`.                     |
| `PANEL_HOST`                 | Public FQDN of the panel, e.g. `vpn.example.com`. Used for subscription URLs (always `https://`) and Caddy's TLS request.                                        |
| `JWT_SECRET`                 | ≥32 chars, random. Signs the session cookie + API JWTs. Rotating it logs everyone out.                                                                           |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | Bootstrap admin created on first run if not present. Change the password immediately after deploy.                                                          |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | Postgres creds. Docker creates the DB on first start.                                                                                |
| `PANEL_REALITY_PRIVATE_KEY` / `PANEL_REALITY_PUBLIC_KEY` | The Reality keypair for *all* inbounds the panel xray serves. Generated by `xray x25519` during `install_panel.sh`. **Rotating these invalidates all subscription URLs.** |

## Optional / tunables

| Var                            | Default                            | Effect                                                                                                                                 |
|--------------------------------|------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| `DATABASE_URL`                 | derived from `POSTGRES_*`          | Async SQLAlchemy connection string. Override if you point at an external Postgres.                                                     |
| `REDIS_URL`                    | `redis://redis:6379/0`             | Used by ARQ for the cron job queue.                                                                                                    |
| `PANEL_XRAY_API_ADDR`          | `host.docker.internal:10085`       | Where the panel's xray gRPC API lives. Inside compose, `host.docker.internal` resolves to the host's docker bridge IP.                 |
| `PANEL_XRAY_CONFIG_PATH`       | `/xray/config.json` (in container) | Where the panel writes the generated xray config. The host bind-mounts `/usr/local/etc/xray:/xray`.                                    |
| `PANEL_REALITY_DEST`           | `www.microsoft.com:443`            | The destination Reality forwards unauthenticated probes to. Pick a high-traffic, fronted-by-Cloudflare-or-similar target.              |
| `PANEL_REALITY_SERVER_NAME`    | `www.microsoft.com`                | The SNI Reality presents to clients. Must match (or be in) the destination's cert.                                                     |
| `PANEL_INBOUND_PORT_START`     | `10001`                            | Lowest port the node allocator will assign to new inbounds.                                                                            |
| `PANEL_INBOUND_PORT_END`       | `10999`                            | Highest port. Must match the UFW range opened by `deploy.sh`.                                                                          |

JWT details (rarely changed):

| Var                  | Default | Effect                                                                                                                                   |
|----------------------|---------|------------------------------------------------------------------------------------------------------------------------------------------|
| `JWT_ALGORITHM`      | `HS256` | Algorithm used to sign tokens. (Hardcoded — change in `config.py` if you really need it.)                                                |
| `JWT_TTL_MINUTES`    | `1440`  | How long a session cookie / API token is valid. Default = 24h.                                                                           |

## Network ports

| Port             | Direction | Opened by   | Purpose                                                              |
|------------------|-----------|-------------|----------------------------------------------------------------------|
| 22/tcp           | inbound   | `deploy.sh` | SSH                                                                  |
| 80/tcp           | inbound   | `deploy.sh` | Caddy ACME HTTP-01 challenge                                         |
| 443/tcp          | inbound   | `deploy.sh` | Caddy HTTPS terminator → panel-api                                   |
| 10001–10999/tcp  | inbound   | `deploy.sh` | xray relay inbounds (one per node, dynamically allocated)            |
| 10085/tcp        | inbound   | **not opened** in UFW | xray gRPC API; reachable only from the docker bridge       |
| 8000/tcp         | inbound   | not opened  | panel-api inside the docker network (Caddy reverse-proxies to it)    |

## File locations on the host

| Path                              | What's there                                                       |
|-----------------------------------|--------------------------------------------------------------------|
| `/opt/accelerator`                | Git clone of the repo                                              |
| `/opt/accelerator/panel/.env`     | Generated by `deploy.sh` — interpolates secrets + overrides       |
| `/root/.panel-secrets.env`        | Stable secrets (JWT, admin pass, Postgres pass, Reality keys)     |
| `/usr/local/bin/xray`             | xray binary (panel relay)                                          |
| `/usr/local/etc/xray/config.json` | xray config — **regenerated by panel-api on every change**         |
| `/usr/local/bin/xray-watcher.sh`  | inotify loop that restarts xray on config change                   |
| `/etc/systemd/system/xray.service`  | xray systemd unit                                                |
| `/etc/systemd/system/xray-watcher.service` | watcher systemd unit                                      |
| `/etc/docker/daemon.json`         | Docker config including the gcr.io mirror                          |

## Compose env interpolation

`panel/.env` keys feed both:

1. Docker Compose's substitution (`${VAR:-default}` in `docker-compose.yml`).
2. The panel process's actual environment.

There is no `env_file:` directive — env vars are listed explicitly so it's
obvious what gets passed to each container. Both `panel-api` and
`arq-worker` share the **same** env block via a YAML anchor
(`environment: &panel_env` on panel-api, `environment: *panel_env` on
arq-worker). If you add a new env var the worker needs, putting it on
`panel-api` is enough.

## Per-node values (set automatically, not env)

These live in the `nodes` table and are picked when a node is created:

- `panel_inbound_port` — free port from `PANEL_INBOUND_PORT_START..END`.
- `panel_inbound_tag` — `in-<cc>-<4hex>` (e.g. `in-de-a1b2`).
- `panel_outbound_tag` — `out-<cc>-<4hex>`.
- `reality_short_id` — random 8-char hex.
- `s2s_password` — random 32-byte hex; set by bootstrap and parsed from
  its final-line JSON, or entered manually for the "register
  pre-existing node" flow.
- `s2s_sni` — TLS SNI presented to the node. Defaults to the node's
  hostname; can be edited.
- `s2s_allow_insecure` — true if the exit uses a self-signed cert
  (`bootstrap_node.sh` generates one).

You can edit `host`, `ssh_port`, `s2s_password`, `s2s_sni`,
`s2s_allow_insecure`, and `status` after creation — see the Edit page in
the admin UI. The other fields are locked because subscription URIs out
in the wild encode them.

## When to bump what

| Reason to change         | Files to touch                                                                            |
|--------------------------|-------------------------------------------------------------------------------------------|
| New Reality destination  | `PANEL_REALITY_DEST` + `PANEL_REALITY_SERVER_NAME` in `.env`. Edit any node → Save to rebuild xray config. |
| Allocate more relay ports| Open the range in UFW + change `PANEL_INBOUND_PORT_END`. Rolling upgrade.                |
| Tighten JWT TTL          | `JWT_TTL_MINUTES` in `.env`. Restart panel-api.                                          |
| Rotate JWT secret        | New random ≥32 chars → restart. All sessions invalidated.                                |
| Rotate admin password    | Use the UI, not the env. `ADMIN_PASSWORD` only seeds on first boot.                      |
